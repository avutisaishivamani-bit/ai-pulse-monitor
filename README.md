## Project Overview
PulseMaintain AI is an end-to-end simulation of an Industrial IoT predictive maintenance system. It demonstrates how machine learning models can predict equipment failure and remaining useful life (RUL), while also showcasing basic MLOps practices like model versioning, drift detection, and automated retraining.

## Features
- **Asset Simulation**: Simulates 8 industrial machines over 400 operating hours, with gradual degradation and sudden calibration drift.
- **Predictive Maintenance**: Uses Random Forest algorithms to predict RUL and failure probability within the next 48 hours.
- **Alerts & Work Orders**: Automatically generates alerts when risk thresholds are exceeded and assigns them to available technicians.
- **MLOps & Drift Monitoring**: Tracks model performance, evaluates drift using Population Stability Index (PSI) and Kolmogorov-Smirnov (KS) test, and triggers retraining when data distributions change.
- **Interactive Dashboard**: A Streamlit interface to visualize telemetry, asset health, open work orders, and MLOps metrics.
- **REST API**: A FastAPI backend providing access to telemetry and system status.

## Module Explanations
- **`simulator.py`**: Generates raw sensor readings based on a gradually decreasing health score. Introduces deliberate calibration drift at hour 200.
- **`ingestion.py`**: Applies a Moving Average (window=5) filter to raw readings to smooth out noise before saving them to the database.
- **`inference.py`**: Extracts the rolling standard deviation of vibration, prepares training sets, and makes predictions using the active ML models.
- **`drift.py`**: Compares the distribution of recent predictions against a historical baseline using PSI and KS-test. If PSI > 0.25 on two consecutive checks, it flags a drift event.

## Database Tables
- `Industrial_Asset`: Tracks machine IDs, names, health scores, and operating hours.
- `Sensor`: Maps sensor IDs and types to assets.
- `Telemetry_Data`: Stores raw and filtered sensor readings for every hour.
- `ML_Model` & `Model_Version`: The model registry storing metadata, metrics, and artifact paths for each trained iteration.
- `Prediction_Log`: Records every RUL and failure probability prediction made by the system.
- `Model_Drift_Metric`: Logs the results of periodic drift checks.
- `Maintenance_Alert` & `Work_Order`: Tracks alerts generated by the system and the technicians assigned to fix them.
- `Technician`: Directory of available maintenance staff.

## Machine Learning Explanation
The system trains two models at hour 50 using accumulated simulated data:
1. **RUL Predictor (RandomForestRegressor)**: Predicts remaining hours before failure.
2. **Failure Predictor (RandomForestClassifier)**: Predicts the probability of failure within 48 hours.
Both models use filtered vibration, temperature, pressure, and the rolling standard deviation of vibration as input features.

## Drift Detection and Retraining
At simulated hour 200, a calibration error artificially raises sensor readings. The system's predictions will shift accordingly. Every 20 hours, `drift.py` calculates the Population Stability Index (PSI). The shift at hour 200 causes PSI to spike > 0.25. When this happens twice consecutively, the pipeline automatically calls `inference.py` to retrain the models on the newer, shifted data, simulating an MLOps automated recovery process.

## Known Limitations
- The simulated degradation is linear and highly predictable compared to real-world mechanical wear.
- The training datasets are very small (simulated hours), meaning evaluation metrics might fluctuate.
- Real-world drift detection usually requires complex delayed ground-truth pipelines; this simulation uses predicted distributions to approximate drift detection.

## Beginner-Friendly Viva Questions

1. **What is Predictive Maintenance?**
   It's a technique that uses data analysis tools and techniques to detect anomalies in operation and predict possible defects in equipment so they can be fixed before they result in failure.

2. **Why use a Moving Average filter on the sensor data?**
   Raw sensor data is often noisy due to environmental factors. The moving average filter smooths out these short-term fluctuations, highlighting longer-term trends that are more useful for the machine learning models.

3. **What is RUL (Remaining Useful Life)?**
   RUL is the estimated amount of time (in hours, days, or cycles) that an asset is expected to operate before it requires maintenance or fails.

4. **Why did you use Random Forest instead of Neural Networks?**
   Random Forests are robust, handle tabular data extremely well without extensive scaling, and train very quickly, making them ideal for this simulation.

5. **What is MLOps?**
   MLOps (Machine Learning Operations) is a set of practices that aims to deploy and maintain machine learning models in production reliably and efficiently.

6. **What is Model Drift?**
   Model drift refers to the degradation of a model's prediction performance over time due to changes in the environment or the relationships between variables (e.g., a sensor degrading or breaking).

7. **How does Population Stability Index (PSI) detect drift?**
   PSI measures how much a population (like the distribution of model predictions) has shifted over time compared to a baseline. A high PSI indicates a significant shift, meaning the model might be operating on unfamiliar data.

8. **What happens in the simulation at hour 200?**
   A calibration drift is introduced where sensor readings suddenly shift (e.g., vibration increases by 1.6). This tests whether the MLOps monitoring system can detect the anomaly.

9. **How does the system handle retraining?**
   If PSI exceeds the threshold of 0.25 on two consecutive checks, the system automatically pulls the most recent data and trains a new version of the models.

10. **Why use SQLite for this project?**
    SQLite is a serverless, self-contained database that requires no configuration. It's perfect for local demonstrations and college projects without needing to set up complex database servers.

11. **What is the Model Registry?**
    It's a centralized repository that tracks the different versions of trained ML models, recording their training time, evaluation metrics, and where the actual model file (`.joblib`) is saved.

12. **How does the system prevent assigning too much work to one technician?**
    When an alert is generated, the system queries the database to find the technician with the lowest count of currently 'OPEN' work orders and assigns the new task to them.

13. **Why do you use Joblib to save models?**
    Joblib is highly optimized for saving large NumPy arrays, which makes it faster and more efficient than standard Pickle for saving Scikit-learn models.

14. **What is the difference between the RUL model and the Failure model?**
    The RUL model is a *Regressor* that outputs a continuous number (hours remaining). The Failure model is a *Classifier* that outputs a probability (0% to 100%) of failure occurring within a specific window (48 hours).

15. **What is the purpose of FastAPI and Streamlit in this project?**
    FastAPI provides the backend infrastructure allowing external systems (like IoT gateways) to send data programmatically. Streamlit provides the frontend UI for human operators to monitor the system visually.
